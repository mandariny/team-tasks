# User Stories — Team-Tasks

> **페르소나 1 — 일반 직원 (Assignee)**

### 도출된 핵심 기능 (MVP 범위)

1. **내 일감 목록 조회** — 로그인하면 자신에게 할당된 일감만 필터링해 표시
2. **일감 상세 조회** — 제목·설명·담당자·마감일 확인
3. **상태 변경** — 대기 → 진행 중 → 완료 (단방향 토글)
4. **마감일·우선순위 정렬** — 목록 기본 정렬 기준
5. **완료 일감 구분 표시** — 완료 항목은 시각적으로 구별(취소선 또는 별도 섹션)

## 2. 결정 사항

1. **담당자도 상태를 직접 변경할 수 있는가?**
   팀원이 자신의 일감을 대기 → 진행 중 → 완료로 바꿀 수 있는지, 아니면 상태 변경 권한을 팀장에게만 부여하는지 결정이 필요하다.
   > **결정: 허용.** 담당자가 자신의 일감 상태를 직접 변경할 수 있다. 팀장이 매번 상태를 대신 바꾸는 구조는 병목을 만들고 실시간성을 해치므로, MVP에서는 담당자에게 상태 변경 권한을 준다.

2. **상태를 이전 단계로 되돌릴 수 있는가?**
   '완료'로 표시한 일감을 '진행 중'으로 되돌리는 역방향 전환을 허용할지, 아니면 단방향(대기→진행→완료)으로만 운영할지 결정이 필요하다.
   > **결정: 허용.** 실수나 재작업 발생 시 되돌릴 수 없으면 이중 일감을 만들게 된다. MVP에서는 어느 방향으로든 상태 전환을 허용하되, 완료→대기 같은 2단계 역행은 UX상 경고 없이 허용한다.

3. **일감에 우선순위 필드를 별도로 둘 것인가, 마감일만으로 순서를 결정할 것인가?**
   시나리오에서 "우선순위 기준 정렬"이 언급되었으나, MVP에 별도 우선순위 값(높음·보통·낮음)을 추가할지 아니면 마감일 순으로만 정렬할지 결정이 필요하다.
   > **결정: 마감일 단일 정렬.** 우선순위 필드는 팀마다 기준이 달라 초기 도입 마찰을 높인다. MVP에서는 마감일 오름차순을 기본 정렬로 쓰고, 우선순위 필드는 v2에서 추가한다.

4. **새로 할당된 일감을 별도로 알려주는 알림 기능이 필요한가?**
   팀원이 09:05에 "어제 퇴근 후 추가된 일감"을 발견하는 시나리오에서, 앱 내 뱃지·이메일·푸시 등 별도 알림을 MVP 범위에 포함할지 결정이 필요하다.
   > **결정: 제외.** 알림 인프라(이메일·푸시)는 1일 구현 범위를 초과한다. MVP에서는 목록 상단에 "새 일감" 뱃지(읽음 처리 없는 단순 표시)만 두고, 실시간 알림은 v2로 미룬다.

5. **'내 일감' 외에 팀 전체 일감 목록을 팀원도 볼 수 있는가?**
   팀원이 자신에게 할당된 일감만 조회하는지, 아니면 팀 전체 일감을 열람(읽기 전용)할 수 있는지 접근 범위에 대한 결정이 필요하다.
   > **결정: 열람 허용(읽기 전용).** 팀원이 동료 진행 상황을 모르면 중복 작업·의존성 충돌이 생긴다. MVP에서는 전체 일감을 읽기 전용으로 공개하되, 상태 변경은 본인 일감에만 가능하도록 제한한다.
